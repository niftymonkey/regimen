## How to run this (read first)

- SEQUENTIAL, not parallel. The whole tree is shared mutable state and every step funnels to one workspace `bun run check`; do NOT fan out the steps or the within-step repoints (work-router: never fan out shared-mutable-state work). Run one off-thread agent per step, in order, each carrying its done-contract; the main thread orchestrates and runs the HITL gates only, so it stays light.
- HITL GATES (never auto-do these): committing, pushing, merging, and archiving/deleting the source repos. The working-tree restructure is git-reversible and delegable; the irreversible git acts are the user's explicit go.
- BRANCH: the consolidation is a CODE change, so it runs on a feature branch in the `regimen` repo (e.g. `monorepo-consolidation`), not on `main`. ADR-0010 rides the same branch and merges with it. The driver doc (`four-harness-evaluation-readiness.md`) and this playbook stay living working-tree files (uncommitted) per the project convention; they travel across the branch switch.
- FIRST ACTION on the user's go: flip ADR-0010 Status `proposed` -> `accepted`, create the feature branch, then delegate Step 2.
